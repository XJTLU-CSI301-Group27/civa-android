# ADR-002 候选幂等摘要格式

状态：候选，尚未用于已发布请求。JSON 请求摘要采用 SHA-256，输入依次为大写 HTTP 方法、规范路径和规范 JSON 的 UTF-8 字节；每段前写四字节大端有符号长度，缺少请求体的长度为 -1。路径必须是 `/api/v1/` 下的未编码路径，UUID 路径段转小写。JSON 对象键按字符串顺序排列，按请求 schema 补全缺失的可空字段为 null；数量字符串去掉多余零，数组保留原顺序。

重复键、未知属性、非法数量格式及不支持的 schema 被拒绝。规范化不替代完整 schema 校验、日期有效性、业务规则和权限检查。multipart 的文件摘要与表单规范化尚未实现。客户端不计算此服务端去重摘要。格式一旦写入共享数据库，不得无迁移地变更，否则旧请求无法正确重放；正式契约、调用方、生成选项和变更登记完成前不冻结此决定。

家庭接口在计算摘要前，按业务规则修剪家庭名称，并将邀请码移除空白、转大写、验证规范 Base32；同一个 key 重试这些等价输入时复用原响应。运行时从随服务端 JAR 打包的同一 OpenAPI 文件读取请求 schema；HTTP JSON 解析拒绝重复键、未知字段和尾随数据。该摘要规则仍为候选，不能直接视作已获团队授权的公共基线。
