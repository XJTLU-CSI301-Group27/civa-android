# C 原生冰箱页面入口与演示接入

日期：2026-11-22，Asia/Shanghai。提供方 AC/C，消费者 EF/F app 装配。
关联 Issue #9（仅后端）；前端扩展来自用户本次明确要求“使用这版 demo 效果做到项目 C 任务前端”。未创建或更改远端 Issue。合并前应另登记 UI Issue，并由团队审阅本候选边界。

状态 PROPOSED：记录本地候选实现，不伪称 EF 已批准或赋予正式门禁授权。

复用现有 Route.INVENTORY、ApiProvider、ApiCalls、SessionStore、NavHost 及全部七个 InventoryApi 操作。不新增路由值、HTTP API、DTO、数据库字段或转换规则。

新增候选入口：

- `edu.xjtlu.civa.feature.ac.inventory.InventoryFragment()`：无参 Fragment，app 在 Route.INVENTORY 装配，内部业务类型不供其他模块使用。
- `edu.xjtlu.civa.feature.ac.inventory.InventoryHost extends NavHost`，提供 `ApiProvider api()`、`ApiCalls calls()`、`SessionStore sessions()`；继承 `void navigate(Route route, String entityId)`，entityId 可空。MainActivity 复用既有实例实现，不暴露 token，不另建客户端。
- 调用线程：UI 主线程；网络异步交给共享 ApiCalls；Fragment/ViewModel 不保留 Activity/View 到业务持久层。

用户已选择演示的冰箱外观和添加/消耗交互。本地实现以 Java + XML/原生 Views 还原，沿用公共 Material 主题和控件；局部 ac_fridge_* 颜色只绘制冰箱插画，不替换全局视觉系统。

数量始终使用 Ingredient.unit；G 显示克、ML 显示毫升；仅 COUNT 且名称含奶时显示瓶，仍表示同一 COUNT。没有容量信息不把瓶数换算毫升。分类写现有 location 字段；旧自定义位置保留单独分组，不擅自更改历史数据。到期日与单位未知值保持未知。

添加和变动先记录 PendingWrite，再提交；未知结果保持原 key/原内容并只允许显式重试；确认或显式结束后删除本地待确认记录。服务器余额确认后重新加载，不使用本地假成功扣减。修改资料使用 expectedVersion，结果不确定提示先刷新核对。所有数量计算使用 BigDecimal 与现有 QuantityInputs。

影响：feature-ac、app 的库存路由装配和候选 public-surface。未改变 A/BD/E 的业务、后端接口或已获批准的公共签名。最终做饭分配接口仍由 IC-9 单独讨论，此页面不独立创建烹饪记录。

验收：开关冷藏/冷冻门、真实库存与批次、添加标准食材、消耗/丢弃/修正、位置/到期修改、临期筛选、空/错误状态、旋转与宽窄布局、重复提交与失败重试；命令与实测证据记录 docs/C_HANDOFF.md。正式审批与最终 main 集成尚未完成。
